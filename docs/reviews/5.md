# Review: #5 Model catalog API

> **Verdict:** Approve · **Merge risk:** Low–Medium · **Read time:** ~10 min
> Plan: `.claude/plans/5-dashboard-v2-catalog.md` · Evidence: `docs/evidence/5.json` · Autonomy: pr

## What and why
`GET /api/models` lists the chat models each of your keys can reach, grouped by provider, with price and context where known. Any listed model now runs straight from Compare without editing `targets.yaml`, and without a `targets.yaml` at all. Typing model ids into YAML was error-prone and went stale. The Models page that uses this comes next.

## Design decisions
| Decision | Chosen | Instead of | Why |
| --- | --- | --- | --- |
| Source | One small httpx fetcher per provider (10 s timeout), run in parallel | A static list | Static lists go stale |
| Catalog id | `<provider>/<id>`, returned as each model's `target`; `targets.yaml` names win | Bare ids | Bare ids broke baseline names and depended on cache order (removed after review) |
| Filter | Provider metadata (Together `type`, Gemini `generateContent`, OpenRouter text output, Groq `active`), LiteLLM `mode` must be `chat` when known, plus an id pattern for embed/tts/image/… | Id patterns only | Fewer false positives. Completion- and Responses-only models can't run through chat completions |
| Prices | Provider price where reported (per 1M USD; OpenRouter `-1` → unknown), else `litellm.model_cost`. Copied into the ad-hoc target so estimates aren't $0 | LiteLLM only | Many OpenRouter/Together models are unknown to LiteLLM |
| Cache | 10 min in-process, per provider and per key fingerprint (sha256), lock-guarded. Failures aren't cached. `?refresh=1` bypasses | No cache | List endpoints are slow and rate-limited. Replacing a key in Settings invalidates its cache |
| Errors | `key_ok:false` with `reason:"no key"` or a short error (`HTTP 401`, exception class), per provider, never a 500 | Failing the request | One broken provider shouldn't hide the others |
| OpenRouter | Also checks `/api/v1/key` | Models list only | The list is public, so it can't validate the key |
| Access | `/api/models` behind the same localhost Host/Origin check as Settings | Open | It uses every stored key and exposes account-specific ids |
| QA | `MODELCOMPARE_CATALOG_FIXTURES` serves recorded JSON per provider (env-only, fixed provider names) | Live calls | Lets the end-to-end journey (AC-9.5) run with fake keys |

## Risks and findings
Reviewer agent: round 1 requested changes (0 High, 7 Medium, 4 Low), all fixed (commit `0d24cc5`). The lead also fixed catalog runs failing with 404 when `targets.yaml` is missing.

| Sev | Finding | Status |
| --- | --- | --- |
| Medium | Bare ids broke baseline/live names and raced the cache | Fixed: removed |
| Medium | OpenRouter `-1` price became negative | Fixed |
| Medium | Estimates ignored catalog prices | Fixed |
| Medium | OpenRouter `key_ok` didn't test the key | Fixed |
| Medium | Cache read/write race | Fixed: lock |
| Medium | `/api/models` had no localhost guard | Fixed |
| Medium | Precedence test was trivial | Fixed |
| Low | Filter ignored LiteLLM `mode` and inactive Groq rows; no pagination; duplicated prefix map; undated Anthropic fixture | Fixed |

Remaining risks:
- Provider response shapes come from their docs. Fixtures are hand-made, not recorded from live accounts.
- A catalog id isn't checked against the catalog, so `openai/typo` starts a run that errors on every call (the report shows Incomplete with the reason).
- Resolving a catalog id on run or estimate may make one provider fetch (bounded by the 10 s timeout and the cache).

## How to test for humans

Where: Not on develop yet
Who: the plan doesn't name an account (local, single user)
About 4 minutes. The automated checks passed. This is what a person can judge that those checks do not.

Nothing to click yet; the Models page comes in the next milestone. With real keys set in Settings:

1. Run `modelcompare serve` and open http://127.0.0.1:8000/api/models
2. You should see each provider you have a key for with `key_ok: true` and a list of chat models (no embedding, TTS or image models), with prices and context where known. Providers without a key show `"reason": "no key"`.
   - Watch for: a model you use every day missing (over-filtering), or an obviously non-chat model listed.
3. Reload with `?refresh=1`. The list is refetched, so it is slower once.
