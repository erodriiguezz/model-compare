# Review: #1 Trustworthy scores

> **Verdict:** Approve · **Merge risk:** Medium · **Read time:** ~15 min
> Plan: `.claude/plans/1-dashboard-v2-scores.md` · Evidence: `docs/evidence/1.json` · Autonomy: pr

## What and why
Provider errors (for example "temperature unsupported" or "credit exhausted") no longer count as wrong answers. Comparisons can now end in two new verdicts: **Equivalent**, a tie within ±3 points, and **Incomplete**, meaning more than 10% of calls errored, so fix the errors and re-run. Benchmarks where every model scores 95% or higher are flagged as too easy. Before this change, errors scored as 0 and ceiling-effect packs pushed most comparisons to "No measurable difference".

## Design decisions
| Decision | Chosen | Instead of | Why |
| --- | --- | --- | --- |
| Errored results | Excluded from score and pairing, counted and reported with their top 3 reasons | Imputing 0.5 | Imputing hides the cause |
| Tie test | TOST-style: the 90% bootstrap CI of the paired delta is fully inside ±`EQUIV_MARGIN` (0.03) | A wide 95% CI read as a tie | A wide CI means "unknown", not "equal" |
| Verdict order | `incomplete` > `insufficient_data` > better/worse > equivalent > inconclusive | The plan's order (insufficient_data first) | A model that errors on every call should point at the errors, not at "not enough tests" |
| Headline | Any `incomplete` benchmark caps the candidate's headline at `incomplete` | Better/worse wins | Same reason: errors make the other verdicts untrustworthy |
| Recommendations | Targets with >10% errors are `not_recommendable`. Cost per case is averaged over successful calls only | Zero-cost errors lowering the average | Otherwise a credit-exhausted model looks cheapest |
| Temperature | `drop_params=True`, plus one retry without temperature when the provider rejects it. Recorded on the completion and in the run's `target_config` | A config-only fix | Covers models the YAML hasn't caught up with. No DB schema change |
| Files outside the plan's list | `runner.py` (2 lines: record the fallback on the run), `schema.py` (1 field), `targets/mock.py` (error and fallback simulation for tests), `recommend.py` (tie tuple) | — | Needed for AC-1.5 and for the tests |
| QA seeding | `app.setup` in `.claude/project.json` seeds one mock run before the server starts | POST /runs inside the smoke | That run is async and raced the /compare check |
| PR size | Added `.github/pr-size-ignore`: the global default plus `**/tests/**` and `**/test_*.py` | Splitting the milestone | The default ignores JS-style tests but missed Python's convention. With it, the PR counts 214 lines |

## How to test for humans

Where: Not on develop yet
Who: the plan doesn't name an account (local, single user)
About 5 minutes. The automated checks passed. This is what a person can judge that those checks do not.

### Old comparisons re-rendered

1. Start the app as usual (`modelcompare serve`) against your real `.modelcompare` data and open the dashboard.
2. Compare two models that previously hit "temperature unsupported" or "credit exhausted" errors.
3. You should see the error count and reason in the warnings, and a verdict of **Incomplete: Fix errors and re-run** wherever more than 10% of calls errored. The score no longer drops because of those errors.
   - Watch for: wording that reads oddly next to the old "No measurable difference" text.
4. Compare two models that score near-identically on the standard deck.
5. You should see **Equivalent (within 3 points)** instead of "No measurable difference", and "Too easy to separate these models" on any benchmark where both score 95% or higher.

### Nearby: should be unchanged

- HTML report export: open a report → every verdict chip has a colour and the glossary lists Equivalent and Incomplete.
- A comparison with a clear winner still reads Better or Worse.

### Not covered by the checks

- A live provider that rejects temperature. The retry is proven only against a mocked LiteLLM. Running one real reasoning model with `temperature` set in `targets.yaml` would confirm it.
